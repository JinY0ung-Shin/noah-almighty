# 외부 아바타 작업 API

외부 시스템이 조건과 지시 내용을 정하고, 개인 API 키 소유자의 **메인 아바타**에게 작업을 요청합니다. 예약 작업을 만들지 않습니다. 기존 채팅 실행 경로를 사용하므로 소유자의 도구 정책, 스킬, 지식과 대화 기록을 사용합니다.

## API 키 발급

Noah에서 **내 아바타 → 권한·연결 → 외부 작업 API**를 열고 키 이름을 입력해 발급합니다. 원문은 발급 시 한 번만 표시되며 서버에는 SHA-256 해시만 저장됩니다. 사용자당 최대 10개입니다.

키는 아래 작업 API에만 사용할 수 있으며 로그인 쿠키나 관리자 API 권한을 대신하지 않습니다. 같은 사용자의 다른 개인 API 키로도 자신의 작업을 조회·응답·취소할 수 있습니다. 키 폐기는 새 요청과 해당 키로 접수된 대기 작업을 차단합니다. 이미 실행 중인 작업은 계속되므로 필요하면 Noah 대화의 중지 버튼이나 취소 API를 사용합니다. 정지된 계정의 키는 사용할 수 없습니다. 키의 "최근 사용" 시각은 최대 1분에 한 번 갱신하므로, 상태를 자주 조회해도 매번 기록되지는 않습니다.

## 이 키의 권한

키는 **로그인한 소유자와 똑같은 권한**으로 동작합니다. 소유자 채팅이 쓰는 모든 도구, 셸에 노출된 비밀값, 지식 저장소 커밋이 그대로 가능하고, 키 소유자는 아래 응답 API로 도구 권한 승인까지 할 수 있습니다. 키가 유출되면 소유자의 로그인 세션이 유출된 것과 같습니다. 비밀번호처럼 보관하고, 의심되면 즉시 폐기하세요.

대신 이 경로로 들어온 턴에는 **외부 시스템이 보냈다는 출처가 함께 전달**됩니다. 아바타는 `message`를 외부 시스템의 데이터로 취급하며, 그 안에 인용된 로그·티켓 문장을 소유자의 지시로 따르지 않습니다. `describe_system`도 현재 턴이 외부 작업 API에서 왔다고 보고합니다. 사람이 함께 있어야 하는 기능은 이 경로에서 빠집니다. 개인 봇 생성 도구(`mcp__personal_agent__create_agent`)는 API 실행에 등록하지 않습니다.

## 작업 접수

```bash
curl "$NOAH_URL/api/v1/avatar/tasks" \
  -H "Authorization: Bearer $NOAH_API_KEY" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: incident-2026-001' \
  -d '{"message":"서비스 A의 오류 로그를 확인하고 원인과 조치 방법을 정리해 줘"}'
```

`NOAH_URL`은 외부 시스템에서 접근할 수 있는 Noah 서버 주소입니다. API 키는 비밀 환경변수로 보관하고 HTTPS로 호출하세요. 서버 간 호출이므로 브라우저 CORS 설정은 필요하지 않습니다.

| 필드 | 의미 |
|---|---|
| `message` | 필수. 자유로운 작업 지시. UTF-8 기준 최대 64KB |
| `conversationId` | 선택. 이어갈 기존 자신의 메인 아바타 대화 ID. 생략하면 새 대화 생성 |

대상 사용자·다른 아바타·권한 상승 옵션은 받지 않습니다. 메인 아바타만 지원하며 개인 봇·그룹 아바타·외부 아바타는 대상이 아닙니다. 현재 입력은 텍스트이며 이미지 첨부나 모델 선택 필드는 없습니다. 모델·도구 선택은 기존 대화와 사용자 기본 설정을 따릅니다. `message`는 아바타에게 그대로 전달하며 UI 전용 슬래시 명령으로 확장하지 않습니다.

접수는 작업을 SQLite에 저장한 뒤 **202 Accepted**와 `Location` 헤더를 반환합니다. 이는 실행 완료를 의미하지 않습니다.

```json
{
  "task": {
    "id": "task-uuid",
    "conversationId": "conversation-uuid",
    "message": "서비스 A의 오류 로그를 확인하고 원인과 조치 방법을 정리해 줘",
    "status": "queued",
    "runId": null,
    "result": null,
    "error": null,
    "createdAt": "2026-09-06T00:00:00.000Z",
    "updatedAt": "2026-09-06T00:00:00.000Z",
    "pendingRequests": []
  }
}
```

`Idempotency-Key`는 선택 사항입니다. 같은 사용자의 동일 키·동일 본문 재전송은 기존 작업을 **200**으로 반환합니다. 같은 키로 본문을 바꾸면 **409**입니다. 호출 타임아웃 후 재시도하거나 외부 이벤트가 중복 전달될 때 사용하세요. 키는 공백 없는 ASCII 1~128자이며 작업 이력이 유지되는 동안 재사용할 수 없습니다.

## 상태·결과 조회

```bash
curl "$NOAH_URL/api/v1/avatar/tasks/$TASK_ID" \
  -H "Authorization: Bearer $NOAH_API_KEY"
```

응답은 `{ "task": ... }`입니다. `GET /api/v1/avatar/tasks`는 최신 100개를 `{ "tasks": [...] }`로 반환합니다.

| 상태 | 의미 |
|---|---|
| `queued` | 실행 대기 |
| `running` | 실행 중 |
| `waiting_input` | 질문·권한·계획·캔버스 입력 대기. `pendingRequests` 확인 |
| `succeeded` | 실행 완료. `result.text`와 `result.summary`에서 응답 확인 |
| `failed` | 실패 또는 제한 시간 초과. `error` 및 대화의 부분 결과 확인 |
| `cancelled` | 취소됨 |

Noah의 대화 목록에도 같은 대화가 표시됩니다. 실행 중인 대화를 열면 기존 스트리밍·질문 UI로 연결됩니다. 대기열에만 있는 작업의 사용자 메시지는 실제 실행 시작 시 기록됩니다. 외부 API의 `result`는 이 작업의 최종 응답이며 전체 대화 기록은 반환하지 않습니다.

아바타가 백그라운드 작업이나 서브에이전트에 일을 넘기면 그 단계가 끝날 때까지 작업은 `running`으로 유지됩니다. 끝나면 `result.text`에 처음 답변과 이후의 모든 백그라운드 보고가 빈 줄로 이어져 담기고, `result.summary`는 마지막 보고의 것을 사용합니다. 진행 중 자리표시자인 "백그라운드 작업을 진행 중입니다."가 최종 결과가 되는 일은 없습니다.

Noah에서 대화를 삭제하면 그 대화의 작업 기록도 함께 사라집니다. 완료된 작업은 목록 조회에서 빠지고 대기 중인 작업은 실행되지 않습니다. 실행 중인 작업이 있으면 먼저 중단한 뒤 삭제하므로, 진행 중이던 작업은 결과 없이 조회되지 않습니다.

## 추가 질문·승인에 응답

`pendingRequests`의 각 항목은 `{ "event": "question", "data": { "requestId": "...", ... } }` 형태입니다. `data`에는 질문 내용 또는 승인 대상이 들어 있습니다.

```bash
curl "$NOAH_URL/api/v1/avatar/tasks/$TASK_ID/respond" \
  -H "Authorization: Bearer $NOAH_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"요청 ID","value":{"result":{"service":"A"}}}'
```

`value`는 해당 요청 종류의 응답 형식을 따릅니다.

- 질문: `{"result": ...}` 또는 `{"cancelled": true}`. 결과 구조는 `data.dialogKind`와 `data.payload`에 맞춥니다.
- 도구 권한: `{"behavior": "allow"}` 또는 `{"behavior": "deny"}`.
- 계획 승인: `{"behavior": "approved"}` 또는 `{"behavior": "rejected", "feedback": "수정 요청"}`.
- 캔버스: 해당 캔버스가 정의한 입력 형식. Noah 화면에서도 응답할 수 있습니다.

성공 시 `{"ok":true}`, 이미 응답했거나 만료된 요청은 **409**입니다. API로 보낸 지시도 기존 승인 정책을 따릅니다. 사용자 브라우저가 필요한 작업은 Noah 브라우저 연결이 있어야 합니다. API가 사용자 브라우저를 대신하지 않습니다.

## 취소·실행 한도·재시작

`POST /api/v1/avatar/tasks/:id/cancel`은 대기 작업을 취소하거나 실행 중인 작업에 중단을 요청합니다. 실행 중 취소는 비동기이므로 상태를 다시 조회하세요. 완료된 작업 취소는 **409**입니다.

디스패처가 작업을 집어 들었지만 아직 실행이 열리지 않은 짧은 구간(`running`이면서 `runId`가 `null`)에서도 취소가 접수됩니다. 실행 직전에 다시 확인하고 그대로 포기합니다. 이 구간에서는 지시 메시지가 대화에 이미 기록된 채 답변이 없을 수 있습니다.

- 사용자당 미완료 작업 최대 20개, 새 작업 접수 분당 최대 60개. 초과 시 **429**, `Retry-After: 60`.
- API 작업은 사용자당 한 개씩, 서버 전체 최대 4개 실행합니다. 같은 대화의 채팅이 실행 중이면 기다립니다. 대화나 지식 저장소가 사용 중이면 다시 대기열로 돌아가며, 재시도 간격은 5초에서 시작해 최대 60초까지 두 배씩 늘어납니다. 계속 사용 중이면 최대 60회까지 재시도한 뒤 그 사유로 **failed** 처리합니다.
- 오래 걸리거나 멈춘 작업은 끝나거나 실패하거나 취소될 때까지 그 사용자의 실행 자리를 차지합니다. 그동안 같은 사용자의 다음 작업은 기다리므로, 멈춘 작업은 제한 시간을 기다리지 말고 취소하세요.
- 디스패처는 약 1초 간격으로 대기열을 확인합니다. 작업 하나의 실행 시간은 `AVATAR_TASK_TIMEOUT_MINUTES` 설정(기본 300분 = 5시간, 최소 1분)을 따르며, 질문 대기 시간과 백그라운드 단계도 포함합니다. 이 시간을 넘기면 작업이 중단되고 **failed**가 됩니다.
- 이와 별도로 대기 중인 요청 하나는 30분 안에 응답하지 않으면 만료됩니다. 질문·캔버스 입력은 취소로, 권한·계획 승인 요청은 거부로 처리됩니다.
- 사람이 지켜보지 않는 실행이므로, 모델 쪽 일시적 오류에는 예약 작업과 같이 하위 모델 등급으로 전환해 이어서 실행합니다.
- 대기 작업은 재시작 후 이어서 실행합니다. 실행 도중 재시작된 작업은 정상 종료·강제 종료를 가리지 않고 **failed**로 표시하며(`cancelled`이 아닙니다) 자동 재실행하지 않습니다. 외부 변경이 일부 수행되었을 수 있으므로 대화를 확인하고 새 요청을 보내세요.
- 새 대화로 접수한 작업이 실행 전에 취소되거나 실패하면(키 폐기, 계정 정지 등) 접수 때 만들어 둔 빈 대화를 함께 지웁니다. `conversationId`로 기존 대화를 이어받은 작업은 대화를 지우지 않습니다.
- 완료된 작업 행을 자동으로 지우는 보존 정책은 아직 없습니다. 행이 남아 있는 동안 같은 `Idempotency-Key`는 계속 예약된 상태입니다.
- 단일 Noah 프로세스·SQLite 배포 구조를 따릅니다. 별도 메시지 브로커는 필요하지 않습니다.

키 관리 API는 로그인 세션으로만 사용할 수 있습니다: `GET/POST /api/me/avatar-api-keys`, `DELETE /api/me/avatar-api-keys/:id`. 생성 본문은 `{"name":"연동 이름"}`입니다.

관리자 감사 로그에는 `avatar_api_key_create`(키 발급), `avatar_api_key_revoke`(키 폐기), `avatar_api_task_accept`(작업 접수), `avatar_api_task`(작업 실행)가 남습니다. 실행 중 도구 사용은 기존 감사 항목 이름을 그대로 씁니다.
